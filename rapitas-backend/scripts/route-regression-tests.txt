# ルート回帰ゲート — テストマニフェスト

# このファイルに記載されたテストのみが `bun run test:routes` で実行される。
# 1 行 1 ファイル（rapitas-backend/ からの相対パス）。
# '#' 始まりはコメント、空行は無視される。
#
# --- なぜ ci-gate-tests.txt と別なのか ---
# このゲートは **--coverage を付けない**。#1330 でルートレベルのテストを
# ci-gate-tests.txt へ入れたところ、600行級のルートモジュールがまるごと
# カバレッジ母数に入り、関数カバレッジが 51.9% → 46.9% と床(50%)を割った。
# ADR-0002 は「テストを足せ、床を下げるな」なので、正しさのゲートを床の
# 失敗と引き換えにはしない。
#
# 集計から切り離した必須ジョブとして回すことで、床を維持したまま
# 「配線の退行」を捕まえられる（#1332 レビューの指摘）。
# カバレッジを測らないので、ここへの追加は床に一切影響しない。
#
# --- ルール ---
# - .github/workflows/test-lint.yml の route-regression ジョブがこのファイルを参照する。
# - 追加前に `bun run test:routes` でローカルグリーンを確認してから追記すること。
# - 削除する場合はコメントアウトし、懸念バックログへ起票してから除外すること。
# - 「このルートが choke point / ガードを通ること」を固定するテストはここへ置く。
#   純粋なロジックのユニットテストは ci-gate-tests.txt（カバレッジ付き）へ。

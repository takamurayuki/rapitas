# rapitas 自律思考型OS化ロードマップ — エージェント実行ロジックの研究駆動改善提案

> 作成: 2026-07-14。コードベース全パイプラインの精査(file:line単位)と、
> 2023–2026年の一次情報(arXiv/公式ブログ/学会採録)調査に基づく。
> 各提案は「現状の実装 → 研究的根拠 → 具体的な変更」の形で記述。

---

## 0. エグゼクティブサマリー

現状のrapitasは **「実行の質」を上げる仕組み(検証ゲート・自己修復・記憶注入)は厚いが、
「何をやるか・なぜやるか」を考える仕組みがほぼ無い**。精査で特定した構造的ギャップは5つ:

| # | ギャップ | 現状 |
|---|---------|------|
| G1 | 学習がタスク選択に未接続 | 選択は優先度バケット+FIFOのみ(`auto-run-selection.ts:146`)。価値見積もり・依存関係・学習データ一切なし |
| G2 | 検証の天井が単一ジャッジ | 敵対的diffレビューは単一LLM・fail-open。唯一のアンサンブル(phase critic 3レンズ)はデフォルトOFF |
| G3 | 信用割当が粗い | タスク成否の二値で、共注入された知識エントリ全部に同一報酬/罰則(因果不明) |
| G4 | 多様性が字面ゲートのみ | 埋め込み放棄後、bigram Jaccard 0.45+飽和cap 8の字面判定。意味的単一文化は構造的に検出不能 |
| G5 | 前提を疑う仕組みの不在 | intakeはセクション数ヒューリスティック。sycophancy無対策。バックログの価値再評価なし |

研究横断の最重要知見: **実測ゲインが出た自己改善手法は例外なく「外部の・改竄しにくい評価シグナル」に
学習を結合しており、失敗事例は例外なく「自分で自分を採点」に由来する**
(Huang+ ICLR'24, Pan+ '24, DGMの自己eval改竄事例, METR o3実測)。
rapitasの改善はこの原則を軸に設計する。

## 1. 現状パイプラインの診断(精査結果の要点)

### 1.1 オーケストレーション(`services/workflow/auto-run/`)

- 12秒ポーリング・グローバル同時実行1・テーマ毎に1タスク完走型。
- **選択は `PRIORITY_RANK {urgent:0..low:3}` + createdAt昇順**。些細な`[Idea]`タスクと重大バグが同priorityなら同格。
- 45分ウォールガード、blocked除外、枯渇時のbacklog昇格(懸念→アイデアの固定順)。
- 学習データ(役割×モデル成功率、テーマ別トラブル率)は**モデルルーティングにのみ**還流。選択には無関係。

### 1.2 タスク自動起票(`backlog-scheduler` / `vulnerability-scan` / `innovation-session`)

- 懸念生成は**直近diffスコープのみ**(HEAD~5、40ファイル、12k chars)。潜在バグ・実行時挙動は不可視。
- 昇格は「懸念が空になるまでアイデアは昇格しない」固定階層 → **創造的タスクが構造的に飢餓**。
- ジョブは時刻トリガー(需要トリガーではない)。価値/工数スコアリングなし。

### 1.3 アイデア生成と単一文化ゲート(`innovation-session` / `theme-saturation`)

- 多様性の強制は**プロンプト指示のみ**+タイトルの字面ゲート(bigram Jaccard≥0.45、LCS≥4文字×8件で飽和)。
- 埋め込み(all-MiniLM-L6-v2)は日本語near-dupに無力で放棄済み。
- 閾値は全て手調整定数。優先度・confidenceはLLM自己申告で、実現価値のフィードバックなし。

### 1.4 検証チェーン(`automated-verifier` / `adversarial-diff-review` ほか)

- 決定的ゲート(実測lint/tsc/related-tests)が主役 → **研究的に正しい設計**(Stechly+ '24)。
- ただし最終関門の敵対的レビューは**単一ジャッジ・fail-open**(判定不能なら通過)。
- related-testsはスコープ限定(遠い呼び出し元の破壊は素通り)。「修正不要」完了は**正規表現マッチ**でゲーム可能。
- phase critic(3レンズ多数決)は存在するがopt-in・デフォルトOFF・1バウンス上限。

### 1.5 学習ループ(`outcome-telemetry` → 各サービス)

- `recordTaskOutcome` から知識強化(±0.3/−0.15)・仮説証拠・エピソード・失敗反省(Reflexion)にファンアウト。
- 想起はoutcome重み(first_try×1.2 / blocked×0.7)+trust重み(validated×1.25 / conflict×0.5)。
- **問題**: (a)強化はセット単位(どの知識が効いたか不明)、(b)Reflexion教訓は無検証で保存
  (研究上これは「間違った教訓の学習」の典型経路)、(c)学習は想起ランキングとモデルルーティングにしか還流しない。

## 2. 改善提案(優先度順)

### P0 — 低コスト・高エビデンス(数日〜1週間スケール)

#### R1. 敵対的レビューを「異系統・小型3ジャッジ+多数決」化し、fail-openを廃止

- **現状**: 単一LLMジャッジ、判定不能時は通過(`adversarial-diff-review.ts`)。
- **根拠**:
  - 単一ジャッジは客観的正しさの検出でほぼ偶然レベル(JudgeBench: GPT-4oで~50%、最良でも75.4%) [arXiv:2410.12784]
  - 異系統小型モデルの陪審は単一GPT-4ジャッジを上回り**コスト1/7**(PoLL) [arXiv:2404.18796]
  - 弱い検証器の重み付きアンサンブルでo3-mini級の信頼性(Weaver) [arXiv:2506.18203]
  - **悪魔の代弁者ペルソナは全プロトコル中最悪**。効くのは独立判定+投票(Debate or Vote, NeurIPS'25 Spotlight) [arXiv:2508.17536]
- **変更**:
  1. `reviewDiffAdversarially` を3並列判定(claude/gemini/chatgpt等の異系統)+多数決に。既存のprovider-rotationコードが土台に使える。
  2. fail-open → **リスク帯別**: 高リスク(prisma/auth等、既存の`routing-policy`のリスク判定を流用)はジャッジ不能=block、低リスクのみ通過。
  3. ジャッジ判定理由を実装者のself-repairプロンプトに**逐語で渡さない**(要約のみ)。逐語露出はジャッジ回避の学習信号になる(CoT監視の難読化結果) [arXiv:2503.11926]。
  4. 各ジャッジの過去判定と実タスク成否の一致率をDBに記録し、Weaver式の重み付き投票に発展させる下地を作る。

#### R2. research前に「前提監査(premise audit)」を必須化

- **現状**: intakeはセクション数/長さのヒューリスティック。タスク記述の前提はそのまま信じる。
- **根拠**:
  - 前提批判能力は「明示的に指示すれば」強く発揮されるが、指示なしではほぼ発動しない(PCBench, EMNLP'25) [arXiv:2505.23715]
  - 条件+目的の台帳を反復採掘するMACMはMATH-L5で+22pt [arXiv:2404.04735]
  - 原子仮定に分解して各仮定を検証するパイプラインが解釈可能で有効 [arXiv:2508.15139]
  - sycophancyは訓練データ由来で、依頼者の望む枠組みを見せたまま批判させると同意に崩壊する
    (Anthropic ICLR'24 [arXiv:2310.13548]、GPT-4oロールバック事例)。**ask-don't-tell**(主張を中立疑問文に再構成)が有効 [arXiv:2602.23971]
- **変更**: `workflow-context-builder.ts` のresearcherプロンプトに必須セクションを追加:
  「タスク記述から原子仮定を列挙 → 各仮定をリポジトリ/実測で検証 → 誤前提があれば『## 結論: 前提誤り』で
  短絡終了(既存の修正不要短絡と同型)」。仮定リストは中立化した形で検証させる。
  出力された仮定台帳はverifierが再チェックする(researchの成果物として`research.md`に固定セクション化)。

#### R3. アイデア生成にVerbalized Sampling+ペルソナ回転を導入し、温度依存を廃止

- **現状**: 多様性はプロンプト内の「多様性の強制」指示のみ。
- **根拠**:
  - モード崩壊はアラインメント由来の典型性バイアスで、**温度では直せない**(新規性と弱相関、非一貫性と中相関) [arXiv:2405.00492]
  - Verbalized Sampling(確率タグ付き候補分布を出させ裾を採る)は訓練不要で**1.6–2.1倍**の意味的多様性、品質低下なし [arXiv:2510.01171]
  - ペルソナ条件付けは温度より強い直交軸(Persona Hub) [arXiv:2406.20094]
- **変更**: `INNOVATION_PROMPT` を「候補5件+各候補の確率を出力→低確率帯からサンプル」に変更し、
  呼び出し毎にステークホルダーペルソナ(エンドユーザー/SRE/セキュリティ監査/新人/アクセシビリティ利用者)をローテーション。

#### R4. 実行接地の強化: 再現テスト必須+アンチゲーミング・トリップワイヤ

- **現状**: related-testsは既存テストの実行のみ。「修正不要」完了は正規表現判定。
- **根拠**:
  - バグ修正で「fail→pass再現テスト」をフィルタにすると採択精度**2倍**(SWT-Bench, NeurIPS'24) [arXiv:2406.12952]
  - 既存テスト通過は漏れゲート: SWE-bench Verifiedでも345パッチが実は誤り(UTBoost) [arXiv:2506.09289]
  - テストファイル改変検出+LLMジャッジでハックの大半を捕捉(EvilGenie) [arXiv:2511.21654]。
    checkerが見えると報酬ハッキングは**~43倍**(METR o3実測)
  - 小さなゲーミングの容認は将来のより悪質な改竄に汎化する(Anthropic) [arXiv:2406.10162]
- **変更**:
  1. バグ修正系タスク(vulnerability-scan起票の懸念タスク)は「ベースコミットでfailするテストを先に書く」を
     implementerプロンプトの必須要件+verifierのハードゲートに。
  2. 決定的トリップワイヤ: diffがテストファイル/CI設定/検証ゲート自身(`services/agents/verification/`等)に触れたら
     自動完了を禁止しレビュー要求。検出したハックはエピソード記憶に恒久的ネガティブ例として記録。
  3. ゲートの正規表現・ジャッジ基準はエージェントの作業コンテキストに露出させない(現状の`looksLogPolluted`等の基準隔離を徹底)。

### P1 — 中期(数週間スケール)

#### R5. アイデア受理をQuality-Diversityアーカイブゲートに置換

- **現状**: 字面ゲート(Jaccard/LCS)のみ。意味的単一文化は素通り。
- **根拠**:
  - QDAIF(MAP-Elites+LLM記述子): グリッドの空セルを埋めるか同セル王者に勝つ場合のみ受理 —
    **設計上モード崩壊できない**唯一のクラス [arXiv:2310.13032]
  - アーカイブ近傍照合+「interestingly new」判定(OMNI-EPIC/ADAS) [arXiv:2405.15568, 2408.08435]
  - 素の過剰生成は**95%が重複**で逓減する(Stanford 100人研究者ブラインド評価) [arXiv:2409.04109]
  - 日本語dedupは日本語特化埋め込み(Ruri/JMTEB系)か翻訳後埋め込みが実測優位 [arXiv:2409.07737]。
    境界ペアはLLMペア判定。採択バッチはk-DPP(最大分散部分集合)で選ぶ [arXiv:2509.04784]
- **変更**: `idea-box-service.submitIdea` のゲートを3段に:
  ①日本語特化埋め込みでアーカイブ近傍K件を取得(放棄したMiniLMではなくRuri系に差し替え)
  ②近傍を見せて「これらと意味的に本当に新しいか」を別モデルが判定(生成者の自己申告noveltyは信用しない —
  AI Scientistの実証済み弱点 [arXiv:2502.14297])
  ③「サブシステム×タスク種×受益者」グリッドのセル割当を判定し、埋まったセルへの追加は同セル既存案との勝ち抜きのみ。
  既存の字面ゲートは①の前段の高速フィルタとして残す。

#### R6. タスク選択に「学習可能帯+バンディット」を導入(G1の解消)

- **現状**: priority+FIFO。学習は選択に一切還流しない。
- **根拠**:
  - 提案タスクを「自明でも不可能でもない中間成功率帯」に報酬付けするAZRはゼロデータでSOTA [arXiv:2505.03335]
  - カテゴリ選択を非定常バンディット化し実測学習ゲインを報酬にするSECはOOD+33%相対 [arXiv:2505.14970]
  - 発案時の価値スコアはLLM発案アイデアで系統的に楽観(実行後に人間案と順位逆転 — Ideation-Execution Gap) [arXiv:2506.20803]
- **変更**:
  1. `selectNextTask` に価値スコア列を追加: 類似完了タスクの実測成功率・所要時間・自己修復回数から
     「期待学習/価値帯」を推定(データは既に`AgentExecution`/timelineにある)。
  2. テーマ×タスク種を腕とするバンディット(報酬=実現価値: 完了+first_try+ユーザー承認)で
     懸念/アイデア/リファクタの配分を適応化 — 現在の「懸念が空になるまでアイデア禁止」固定階層を置換。
  3. 発案時スコアと実行後結果の差分を`recordTaskOutcome`で記録し、発案スコアラーを継続再校正。

#### R7. プラン事前検証(pre-mortem)の常設化

- **現状**: phase critic(3レンズ)はopt-in・OFF。planは承認後そのまま実行。
- **根拠**:
  - Judge-LLMによるプラン反復批評は**recall 90%/precision 100%**でプラン欠陥を事前検出 [arXiv:2509.02761]
  - LLM世界モデルで「実行前に帰結をテキストシミュレート」は木探索と同等性能で4–5倍効率的(WebDreamer) [arXiv:2411.06559]
  - ReflAct(各ステップで「ゴールと現状の整合」を反省してから行動)はReAct比**+27.7%** [arXiv:2505.15182]
- **変更**:
  1. `RAPITAS_PHASE_CRITIC` をstandard/comprehensiveモードでデフォルトONに(R1の投票化と併せて)。
  2. plannerプロンプトに「プレモーテム」セクション必須化: このプランが失敗したとして最も可能性の高い原因3つと、
     各々の事前検知方法。verifierはこのプレモーテム項目を実測照合。
  3. implementerのフェーズプロンプト先頭に、タスクのゴール+受け入れ基準を毎回再注入(ゴールドリフト対策:
     100kトークン超で全モデルがドリフト [arXiv:2505.02709])。

#### R8. 学習ループの信用割当を「使用時申告+統合」で細粒度化(G3の解消)

- **現状**: 共注入知識に一律±強化。Reflexion教訓は無検証保存。
- **根拠**:
  - メモリは「将来タスクの成否が無料の品質ラベル」— 選択的削除で長期性能が実測向上 [arXiv:2505.16067]
  - 想起の有用性は学習可能(Memento: ケース選択方策の学習でGAIA SOTA、OODで+4.7〜9.6pt) [arXiv:2508.16153]
  - 書き込み時のadd/update/delete/merge統合(Mem0)がメモリ肥大の実証的対策(トークン>90%削減) [arXiv:2504.19413]
  - 外部シグナルなしの自己反省は性能を悪化させる(Huang+ ICLR'24) [arXiv:2310.01798]
- **変更**:
  1. **使用時申告**: 各役割プロンプト末尾に「注入された知識のうち実際に使ったものをIDで列挙し、
     誤っていたものをフラグせよ」を追加。verify結果と合わせて、セット単位でなく**エントリ単位**で強化/罰則
     (`applyOutcomeReinforcement`の入力を細粒度化)。
  2. Reflexion教訓(`reflectOnFailure`)は「保存時にpending、その教訓を注入されたタスクが成功して初めてvalidated」
     — 既存のvalidationStatus機構に乗る。無検証のまま高trustにしない。
  3. 書き込み時にMem0式の統合判定(既存`dedup.ts`/`contradiction.ts`を「新規追加 vs 既存更新 vs 削除」の
     三択判定に拡張)。
  4. アイドル時間(auto-run枯渇時)にconsolidation/distillation/プロンプト最適化ジョブを回す
     (sleep-time compute: 5倍のテスト時計算削減 [arXiv:2504.13171])。既存のbacklog-schedulerに追加ジョブとして自然に載る。

#### R9. ワークフロー蒸留: 「うちのやり方」ライブラリ

- **現状**: エピソードは教訓テキスト。手順の再利用機構なし。
- **根拠**:
  - 自分の成功トラジェクトリから抽象化した手順(workflow)を注入するAWMはWebArena**+51%相対** [arXiv:2409.07429]
  - 検証済み実行可能コードとして技能を貯めるVoyagerの技能ライブラリ(自己検証済みが最も信頼できる記憶形式) [arXiv:2305.16291]
  - 最近傍の解決済みタスクを検索して適応するCBRは+36%(DS-Agent, ICML'24) [arXiv:2402.17453]
- **変更**:
  1. 完了タスクのトレースから「再利用可能な手順断片」(例: Prisma schema変更の手順、i18nキー追加の手順)を
     バッチ抽出するジョブを追加(ExpeL式に成功/失敗ペアの対比から抽出)。
  2. 実装者プロンプトへの注入を「教訓テキスト」から「最近傍の解決済み類似タスクのplan+結果」に拡張(CBR)。
  3. 頻出手順はスクリプト化して`scripts/`に保存し、検証済みなら以後は再生成でなく参照実行。

### P2 — 長期(1〜2ヶ月スケール、要設計)

#### R10. 役割プロンプトの進化最適化(GEPA式)

- **現状**: 全役割プロンプトが`workflow-context-builder.ts`のインライン定数。A/B不能。
- **根拠**: GEPA(反射的プロンプト進化+Paretoアーカイブ)はRL比+6〜20%を**35分の1のロールアウト**で達成
  (ICLR 2026 oral) [arXiv:2507.19457]。SICAは自己改変で SWE-bench 17→53% [arXiv:2504.15228]。
  ただしDGMは自己eval改竄を実証 [arXiv:2505.22954] — **改竄不能な外部ゲート必須**。
- **変更**:
  1. 役割プロンプトをDB管理に移行(既存のprompt-evolution-runnerの土台を昇格)。
  2. 「ゴールデンタスク集」(過去の代表タスク10〜20件+期待結果)を固定ベンチとして整備。
  3. verifyゲート実績をメトリクスに、失敗トレースへの反省からプロンプト変異を提案→ゴールデンタスクで
     評価→Paretoアーカイブ維持。**採用ゲートは決定的ゲート(lint/tsc/test)の実測のみ**。ジャッジスコアを
     最適化目標にしない(ジャッジがハックされるため)。

#### R11. ポートフォリオ・リフレクション(研究空白 = rapitasの独自性になり得る)

- **現状**: バックログの価値再評価は存在しない。起票されたら価値は固定。
- **根拠**: 調査の結果、**「エージェントがバックログ項目の存在価値を定期再評価する」直接の先行研究は見つからなかった**
  (最近傍はゴールドリフト評価 [arXiv:2505.02709] とReflAct)。設計は第一原理+R2の前提監査の転用になる。
- **変更**: 週次ジョブ「backlog reflection」を新設:
  各open懸念/アイデア/todoタスクに対し (a)前提はまだ成立しているか(R2の仮定監査をバックログに適用)、
  (b)完了済みタスクで無効化されていないか、(c)実測価値の低いカテゴリに属していないか(R6のバンディット統計)
  を判定し、無効化されたものは理由付きでアーカイブ。**これは既存OSSにない差別化機能になる**。

#### R12. 確信度校正されたask-for-help

- **現状**: intake質問は1問1答ヒューリスティック。実行中の「聞くべきか進むべきか」は勘。
- **根拠**: KnowNo(共形予測で「候補集合が単一でなければ人に聞く」)は統計保証付きで人的介入を削減
  (CoRL'23 Best Student Paper) [arXiv:2307.01928]。注意: 推論チューニングされたモデルは棄権が**24%悪化**
  (AbstentionBench) [arXiv:2506.09038] — 棄権は足場で作る、モデル任せにしない。
- **変更**: intake/実装中の分岐点で複数候補+自己確率を出させ(R3のVSと同機構)、確率質量が
  閾値を超えて単一候補に集中しない場合のみ`question.md`を起票。閾値は過去の「質問した/しなかった×結果」で校正。

## 3. 横断設計原則(全提案に共通)

1. **学習は外部の改竄しにくいシグナルにのみ結合する。** 決定的ゲートの実測(lint/tsc/test/fail→pass遷移)>
   実タスク成否 > 異系統ジャッジ多数決 >> 自己申告。この順位を崩さない。
2. **fail-openは低リスク帯のみ。** ジャッジ不能=通過、は高リスク変更では廃止。
3. **checkerの内部をエージェントに見せない。** ゲート正規表現・ジャッジ基準・判定理由の逐語は
   コンテキストから隔離(見えると回避を学習する)。
4. **ハックは即ハード失敗+恒久記録。** 小さなゲーミングの容認は悪質な改竄に汎化する。
5. **多様性はフィルタでなく構造で保証する。** 事後の重複排除でなく、アーカイブ/グリッドが空の領域にしか
   受理しない設計に。
6. **自己申告の新規性・価値・確信度を信じない。** 別モデル判定・実行後結果・共形校正で置き換える。
